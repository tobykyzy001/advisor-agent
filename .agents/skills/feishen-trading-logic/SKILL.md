# 飞神交易逻辑（Feishen Trading Logic）

这是把「飞神 / 飞大 / 仰手飞猱」风格提炼出来的**交易决策框架层**。它不是通用投资方法，也不是历史回测结果；它必须在实时证据上运行，并与本仓库其它投研技能分层协作。

> 核心要求：**不要从股票名直接跳到买卖结论**。任何结论都按固定顺序建立：先市场闸门，再板块阶段，再个股角色，最后才谈触发、周期、成本、仓位和动作。

使用本技能时必须读取两份参考文件（面板分发时与 `SKILL.md` 同目录；作为本仓库 skill 使用时位于 `references/`）：

- `feishen-rulebook.md`：规则卡，给出收益来源模型、市场/板块/个股/入场/持仓退出/超短规则；
- `feishen-aliases.md`：隐语与股票别名解析。用户出现绰号、谐音、简称、历史价格层说法时必须先查它。

## 第一原则

决策顺序固定：

```text
市场环境
  -> 板块阶段与主线
  -> 个股角色与趋势状态
  -> 结构 / 量价触发
  -> 交易周期
  -> 成本与仓位上下文
  -> 条件动作与失效条件
```

收益来源模型（只作框架，不作公式）：

```text
产业趋势 × 预期差 × 核心公司 × 低成本筹码 × 交易纪律
```

任一环节明显缺失，都降低动作强度。例如：方向正确不等于交易正确；强形态不能越过市场和板块闸门；低成本不能替代趋势与失效条件；长期叙事必须带兑现窗口和中间验证节点。

## 硬边界

- 不编造当前价格、成交量、市场状态、板块强弱、新闻或工具返回证据。
- 个股价格/量能证据优先用 `fetch_quotes.py --snapshot <代码>`（直连 tushare REST；脚本自包含纯标准库，工作区 scripts/ 没有时先从插件端点下载；token 用环境变量 TUSHARE_TOKEN 或工作区 .env）；板块/市场级证据或 token 未配置时证据不足，只能输出「证据缺口 / 候选观察 / 待验证」，不得升级为个股买卖结论。
- 候选池证据只支持**方向级**观察和失效条件；个股级买点、卖点、持有、减仓、退出、具体价格条件，必须先切换到个股/持仓模式。
- 用户聚焦到 1–3 只标的，或询问趋势、空间、买点、风险、剔除条件、当前价格时，要明确说明「已从候选池切换到个股分析」。
- 别名解析必须先查 `feishen-aliases.md`；含混未解且影响结论时要问清或分别分析，不得静默选一只股票。
- 动作用条件式表达：核心观察、候选观察、持有观察、分层参与、做T观察、减仓/回避；禁止输出「必买」「必卖」。
- 技术形态只是确认工具，不能在没有市场环境、板块阶段和个股角色判断时单独升级为信号。
- 历史规则与风格结论不等同于回测结果；证据不足时降级而不是硬推。

## 数据与证据要求

当前执行环境没有 StockAgents bridge；使用本技能时用会话内既有可用数据源替代其候选池证据。优先级：

1. **fetch_quotes.py --snapshot**：个股实时/近实时证据来源（直连 tushare REST）；
2. 本仓库既有数据层或职业技能输出：如 `prosperity-analysis` 的行业景气、`stock-valuation` 的个股估值、`w-bottom-screener` / `momentum-rotation` 的池内信号；
3. 完全没有实时证据时：明确标注证据缺口，只保留规则推理和待验证清单。

常用证据映射（按会话中实际可用工具为准）：

| 判断层 | 可用证据 | 说明 |
|---|---|---|
| 市场环境总闸门 | 大盘指数行情/估值、每日交易统计、涨跌停与连板、市场资金流、南北向资金 | 判定强、弱、中性、高位震荡；不只看单日指数涨跌 |
| 板块阶段 | 行业/概念板块行情、涨停最强板块、热榜、板块资金流、已有景气分析 | 判断是否低位启动、扩展、扩散、补涨、高潮、退潮 |
| 个股角色与趋势 | 日线/周线、每日指标、技术面因子、个股资金流、基本面字段 | 判定趋势核心、阶段题材、短线交易、弱趋势；保留量价与筹码证据 |
| 触发与失效 | 平台突破/回踩、双底、仙人指路、堆量上行、扭转反转、颈线量超、放量不涨 | 逐条对照规则卡；形态只是确认工具 |

> 行情明细数据可能很大，尽量不要把长 K 线序列原样粘贴进主对话；优先取近端摘要、关键指标和可复算的日期/数值。

## 请求分类

先选一个主模式；若多个模式同时命中，取证据要求更强的那个：

- **候选池 / 题材模式**：用户问现在看什么板块、什么方向在增强、下一轮动可能在哪里、哪些票放观察池。
- **对比模式**：用户比较 2–5 只股票或 2–5 个方向。
- **单股模式**：用户问 1–3 之股票、趋势、空间、买点、卖点、当前价格、剔除条件。
- **持仓模式**：用户给出成本、仓位、持有逻辑，问持有、加仓、做T、减仓或回避。
- **复盘模式**：用户问一笔交易为什么成功或失败。

候选池与个股/持仓的边界必须清楚：候选池只做方向级观察和失效条件；个股级执行条件必须升级。

## 工作流程

### 1. 判定市场环境（总闸门）

用当前指数、赚钱效应、连板高度、市场资金流、主线强弱等证据，把环境分成：

- **强**：允许趋势参与和确认突破，但仍要过板块/个股检查；
- **高位震荡**：行情后段战术状态，不是新一轮普涨；聚焦主线核心，低吸、分批兑现、减少仓位容错，不做辅线和无周期依据的超跌反弹；
- **中性**：偏向回踩、平台、分层参与，避免追一致；
- **弱**：不追突破，降仓、等待，优先抗跌和防守；
- **未知**：没有证据就明确说未知，动作降级为观察。

### 2. 判定板块阶段与主线

把板块放到下面路径中：

```text
低位启动 -> 龙头扩展 -> 细分扩散 -> 后排补涨 -> 高潮 / 退潮
```

同时看市场认知扩散曲线：

```text
无人认知 -> 少数人发现 -> 题材命名/主流认可 -> 全民讨论 -> 兑现 / 接力后段
```
- 优先核心股与尚未充分定价的扩展方向；
- 龙头、中军仍扩展且板块容量健康时才允许进攻；
- 后排补涨本身不是更安全；龙头转弱时先降级后排；
- 全民共识、高潮、利好兑现不涨时降低追高意愿。

### 3. 判定个股角色与交易周期

先分类，再谈动作：

- **趋势核心**：产业趋势清晰、板块仍有空间、结构未破；可做中期持有、滚动操作；
- **阶段题材**：催化和轮动驱动，使用有限窗口，不当成永久持有逻辑；
- **短线交易**：情绪周期、分歧/一致或短线结构主导；小仓、快速、明确失效；
- **弱趋势 / 下降通道**：默认减仓或等待结构重建；做T不能掩盖下降趋势。

区分“作者逻辑”与“持有方法”：长期逻辑可能正确，但必须给出兑现窗口与中间验证；短期机会也不需要升级为长期逻辑。

### 4. 检查触发与失效

逐项对照 `references/feishen-rulebook.md` 的 ENT/HOLD/EXIT 规则，特别是：

- 趋势中的回踩、有效平台/颈线突破、突破失败回到平台、双底不再创新低、仙人指路、堆量上行、空头承接覆盖、扭转乾坤、颈线位量超、上行筹码压力；
- 建设性回撤与破坏性回撤必须分开：趋势中的缩量回踩、承接稳定、结构未破，可能是建设性；高位放量滞涨、支持失守、资金撤出，是破坏性；
- 一次强势、单日抗跌、单一利好只是证据点，必须反复确认。

### 5. 应用成本、仓位与预期窗口

- 低成本可提高波动容忍度，但不能免死；
- 战略预期与战术仓位分层：预期未变可保留战略仓，阻力和加速阶段用战术仓兑现，确认后再补；
- 阶段题材和短线仓位不能静默转成长线持有；
- 每个中长线结论必须写：该发生什么、何时发生、通过什么里程碑确认、到期没有兑现如何重估；
- 对每段回调明确写建设性或破坏性，并说明会改变分类的证据。

### 6. 生成条件动作

只能从这些动作标签收敛： 核心观察、候选观察、持有观察、分层参与、做T观察、减仓/回避。

每个个股级结论必须给出：主归因行业、个股角色、交易周期、匹配规则、触发条件、持有条件、做T边界（如适用）、减仓/退出条件、失效条件、证据与置信度。

## 与其它技能的分工

- `stock-valuation`：回答「这家公司值多少钱 / 贵不贵」；本技能回答「现在是否适合按飞神体系参与 / 如何对待仓位」。两者互补，不互相替代。
- `prosperity-analysis`：回答行业盈利景气与周期位置；本技能把景气方向放进市场环境、板块阶段与个股角色。
- `momentum-rotation`：给观察仓做月频动量轮动组合；本技能是更主观的阶段/角色/动作判断，不参与其固定排名规则。
- `w-bottom-screener`：只做「W底 + 放量」形态筛点；本技能可以把 W 底当作触碰确认之一，但例如没有行业和角色判断，不能单独升级。
- `watchlist-manager`：观察仓唯一写入口；本技能**默认不把结论写回观察仓**。确需留痕时，必须委托 `watchlist-manager set`，不得直接修改 `output/watchlist/watchlist.yaml`。

## 免责

本技能输出仅供研究参考，不构成投资建议。风格规则不构成回测结果；市场、板块、价格和基本面证据必须标注时点与来源。
