# 研报阅读（Report Reading）

读一份卖方研报，把它拆成**可核查的主张**，做一轮**只找证据**的批判性核查，然后在「采信账本」上明确每条主张采信了谁，最后才用**采信后的预测**推估值结论。

## 什么时候用它

- 用户发来研报正文/链接/PDF 转出的文本，问「读一下」「靠谱吗」「按它的预测算算值多少」「目标价合理吗」「这份研报说的是真的吗」。
- 研报里的预测要进入后续判断（估值/观察仓/持仓复核），需要一份**可回溯的采信依据**——哪些数字采信了、依据是什么、哪些被证据推翻。
- 投研流程内委托调用：`prosperity-picking` 选股时拿到卖方预测、`stock-valuation` 需要前瞻口径的分母时，可用本技能的脚本把研报预测落成结构化采信账本。

## 核心信念：批判性阅读 ≠ 否决研报

核查只做一件事：**找证据**。

- **有证据证伪**（报告内部算术自相矛盾 / 行文与表格数打架 / 与已披露实际值冲突 / 评级与目标价方向矛盾）
  → 该主张不采信：能用证据值替代的就替代（**overridden**），替代不了的**作废**（**rejected**）；作废的主张绝不带进估值。
- **拿不出证据**（无外部数据、与一致预期有分歧、报告偏旧、增速异常、覆盖机构少）
  → **默认采信研报估算**，只把疑点登记为 caveat / 缺口 / 风险，**不擅自给研报数字打折**。

为什么必须这样：卖方预测的误差方向**不可预知**，「我感觉它偏乐观」不是信息、只是噪声；而无证据的自行下调会让结论无法回溯、也无法被后续数据检验。把不确定性写进**缺口与风险清单**，比偷偷把净利乘 0.8 更诚实，也更有用。

## 证据等级（冲突时的裁决规则）

| 等级 | 内容 | 例 |
|---|---|---|
| 1（最高） | 已披露实际值 | 表格 `20XXA` 列、财报实际数、外部实测注入 |
| 2 | 报告表格绝对数 | 预测表里的归母净利润/营收/EPS（可复算、可交叉核对） |
| 3（最低） | 报告行文措辞 | 同比增速、形容词、评级文字 |

- 高等级胜低等级：如「行文写增速 18.8%，但表格绝对值复算只有 12%」→ 采信表格复算值，把行文增速当作废措辞。
- 同级冲突且无法裁决 → 该字段作废并如实标注，**不做猜测**。

## 三步流程

### 第 1 步：取正文 + 抽主张（脚本，不经过 LLM 手抄）

脚本真源 `src/workspace-init/report_reader.py`（纯标准库、自包含），随插件包分发、由投研工具面板
在投递指令前预置到工作区 `scripts/`（经宿主 `/provision` 端点白名单直写），直接运行：

```bash
# 入口一个参数：本地文件（.txt/.md/.html）或 http(s) 链接；PDF 需先转文本
python scripts/report_reader.py --input <文件或链接> --text-out output/research/body.txt --no-report
```

- 自动抽取：标的/机构/日期/评级/目标价/自述估值锚（如「给予 2027 年 25 倍 PE」）/分年度预测表（含 `A`/`E` 列区分实际与预测）/增速行。
- **抽不到的字段进 gaps 如实列出**（不猜）。缺口由会话读正文后补成 `claims.json`，用 `--claims` 传回：

```bash
python scripts/report_reader.py --input <入口> --claims output/research/claims_x.json \
  --snapshot-file output/research/snapshot_x.txt --consensus-file output/research/consensus_x.txt
```

`--claims` 字段表见脚本头部 `CLAIMS_SCHEMA_DOC`；单位：净利/营收**百万元**、EPS/价格**元**、总市值**亿元**。

### 第 2 步：批判性核查（脚本内的 A 系列清单，逐条给证据与处置）

| 编号 | 查什么 | 判定 |
|---|---|---|
| A1 | 目标价 vs 自述估值锚（EPS × 给予PE） | 偏差 >5% → **证伪**，目标价改用报告自身锚重算值 |
| A1b | 评级方向 vs 目标价空间 | 买入却目标价 ≤ 现价（或反之）→ **证伪**，目标价作废 |
| A2 | 行文增速 vs 表格绝对值复算 | 偏差 >3 个百分点 → **证伪**，采信表格复算增速 |
| A3 | EPS vs 净利÷股本（用快照总市值/现价推股本） | >20% → **证伪**，EPS 作废（估值主口径走市值+净利）；10–20% → 存疑（摊薄口径） |
| A4 | 同年预测 vs 已披露实际值 | >10% → **证伪**，采用实际值（实测优先） |
| A5 | 报告新鲜度（距今 >180 天） | **存疑**，登记预测滞后，数字不变 |
| A6 | 与机构一致预期偏离（>30%） | **存疑**，只做差异分析，**绝不据此改研报数字** |
| A7 | 缺口（缺目标价/评级/预测/现价/一致预期） | 登记，结论限定在可用字段内 |

取证据走统一口径，数字不经过会话手抄：`fetch_quotes.py --snapshot <代码>` 出快照（现价/总市值/PE/PB/股息率）、
`fetch_forecast.py <代码> --mcap <总市值亿元>` 出机构一致预期；两者输出重定向到文件后由脚本自己解析。

### 第 3 步：采信账本 → 估值桥

- **采信账本**：逐条列「主张 / 采信值 / 状态（assumed·采信原值｜overridden·按证据替换｜rejected·作废｜missing·缺口）/ 依据」。
- **估值桥**（只在采信后的预测上算）：
  - 前瞻PE：**市值口径**（总市值 ÷ 采信净利），不受股本/摊薄口径影响；逐年给出并以**研报自述锚年**为前瞻年（沿用研报口径，不偷换年份）。
  - PEG = 前瞻PE ÷ 该年净利增速；增速非正时明示「PEG 不适用」。
  - 目标价空间、自述锚复核价、合理价区间（采信预测 × 合理PE 区间）、相对保守合理价的溢/折价。
  - **现价隐含要求**：按 PEG=1 口径，现价对应的前瞻PE 就是市场要求的净利增速——低于它性价比转差。
  - **方向结论**：前瞻PE 低于保守倍数 → 便宜；落在通用区间内 → 合理；超中性倍数 → 贵。
  - 与一致预期差异的六类定性：预期透支 / 预测滞后 / 覆盖不足 / 年内进度不符 / 口径差异 / 独立判断。
- **合理PE 是显式假设**：默认区间（`--pe-band 8,25`）只是通用观察区间，**未做质量溢价/行业β 校准**。
  高 ROE、现金流转化好的标的通常享有质量溢价（不能用行业平均 PE 套龙头）；周期/高β标的应压低倍数。
  要换口径就传 `--pe-band`，并把这个假设写进结论里。

## 输出格式（结构化，供研报/后续决策用）

```
标的: <代码/名称>  <研报来源与时间>  数据时点: 快照日期 / 一致预期抓取时点
研报要素: 机构/分析师/日期/评级/目标价
核查发现: 证伪 N 条（列出：对象 + 证据 + 处置）｜存疑 M 条（列出，明确「不改数」）｜说明 K 条
采信账本: <逐条 主张/采信值/状态/依据>
采信后预测: <年度 净利/增速/EPS（标注哪些被证据替换过）>
估值桥: 前瞻PE（市值口径）· PEG · 逐年PE · 目标价空间 · 自述锚复核 · 合理价区间 · 现价隐含要求
方向结论: 便宜 | 合理 | 贵（附安全边际与所用倍数假设）
与一致预期差异: <逐年度偏离% + 差异原因定性 + 采信立场>
缺口与风险: <数据缺口 + 报告风险提示 + 存疑项 + 作废主张>
关键节点: 等财报验证兑现 / 等销售月报 / 等价格库存拐点 / 等现金流分红
```

## 与其它技能分工

- `stock-valuation`：**该给几倍**（生意属性 → 估值口径 → 质量溢价/行业β 校准）；本技能：**假设哪个盈利数**（研报预测的采信账本）。两者串联使用：本技能出采信后的预测与前瞻PE，stock-valuation 判倍数是否合理。
- `prosperity-analysis`：行业景气度（自上而下），本技能是个股级研报落地。
- `portfolio-tracker` / `watchlist-manager`：本技能结论若要跟踪，**委托**它们落地（观察仓写入唯一走 `manage_watchlist.py`），本技能不直接改清单。
- `w-bottom-screener` / `momentum-rotation`：形态与动量信号，与本技能无关（不同维度）。

## 常见陷阱自检（输出前逐一过）

- [ ] 是否把「存疑」说成了「研报错了/不可信」？（存疑 ≠ 证伪，措辞必须区分）
- [ ] 是否在没有证据的情况下自行下调了研报的盈利预测（打折、砍增速）？（禁止）
- [ ] 是否把与一致预期的分歧当成证伪证据？（一致预期同样会错）
- [ ] 是否用静态 PE/PB 给研报预测标的下了「贵/便宜」结论？（须用采信后的前瞻口径）
- [ ] 前瞻年是否偷偷换成了对自己结论有利的年份？（必须以研报自述锚年为准并写明）
- [ ] 合理PE 倍数是否被当成事实而不是假设？（须写明假设与「未做质量溢价校准」）
- [ ] 缺口（PDF 未转文本、无机构覆盖、取数失败）是否如实说了，而不是拿估算凑？
- [ ] 行情/一致预期数字是否经过了手工转抄？（须经文件传给脚本，避免转抄出错）

## 生成数据 vs 技能方法（提交边界）

- **提交**：本技能（`SKILL.md`）与脚本真源 `src/workspace-init/report_reader.py`（方法/工具，随仓库与插件分发）。
- **不提交**：研报正文、`claims.json`、快照/一致预期证据文件、生成的 `output/research/report_*.md|.json`（均为运行时/易过期/可能含个人关注标的，`.gitignore` 已覆盖）。
