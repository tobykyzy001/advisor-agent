# 抄作业 · 别名 → 标的映射

群主/大V在作业里几乎不写代码，而是用**题材黑话 / 圈子昵称 / 简称**称呼标的。要把路线送去回测，必须先把这些别名落成确切的 `ts_code`。本文件说明映射规则、自动推断逻辑，并维护一张**已确认映射表**。

## 映射优先级（symbol_map.py 的加载顺序）

1. `output/copy-trade/alias-map.override.yaml` —— **运行时现场确认的覆盖**（你与 agent 确认后回写，优先加载；不回写仓库）。
2. 本文件末尾的 `confirmed_map` —— **已随仓库提交的常识映射**（题材→标的，不含个人交易信息）。
3. 脚本对"消息里出现的具体中文/代码"的**实时自动推断**（用 tushare `stock_basic` 按名称反查 ts_code）。

优先级越高越先命中；同优先级命中多条时输出候选让用户确认。

## 自动推断规则

- 消息里出现 **6 位数字**：直接当作代码，按交易所补后缀（沪 `60/68`→`.SH`，深 `00/30`→`.SZ`，北交所 `8/4`→`.BJ`）。
- 出现 **2~4 字中文 + 罕见词**（如"联瑞新材""申菱环境"）：用 `mcp__tushareMcp__stock_basic` 的 `name` 反查 `ts_code`；多码命中（A/H/多后缀）则输出候选。
- 出现**题材/黑话**（冷液、硅微粉、燕子家族、折叠、铜箔、特高压、电源…）：只能靠 `confirmed_map` 或人工确认，脚本**不臆断**，输出"待确认"。

## 为何不自动猜黑话

黑话有歧义（"冷液"可能指冷板也可能指液冷温控整机，"燕子"是群主对"有研"的昵称），猜错会把回测算到错误的标的上，产出方向性误导的错误结论。宁可标注"待确认"也不硬猜，是可信度评估的原则。
