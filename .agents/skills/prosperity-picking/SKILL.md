# 景气板块选股（Prosperity Picking）

把「景气投资」落成一条可持续跟踪的流水线：**先维护一份当前跟踪的景气板块清单，再从这些板块里选出高相关标的、按景气口径估值后放进观察仓**。核心信念同 `prosperity-analysis`：景气度（盈利增速方向）决定相对收益，估值决定回撤——本技能是它的**执行层**（板块进出 + 标的落地），不重复其方法论细节。

> 定位：这是一个**组合工具**（两段式流水线），把 prosperity-analysis（板块景气判断）、stock-valuation（景气口径估值）、watchlist-manager（观察仓写入）串成闭环，并自己维护一份跨轮次的**景气板块跟踪状态**（`output/prosperity/state.yaml`）。

## 何时触发

- 用户说「筛一下当前有哪些景气板块」「复核一下我的景气板块还在不在」「初始化景气板块」。
- 用户说「从景气板块里选股」「选一批景气标的」「把景气投资组合建起来」。
- 投研工具面板：侧边栏「景气板块选股」卡片（动作 screen 筛选/复核景气板块、pick 选出景气标的）。

## 两段式流程（严格按动作分流，不混跑）

```
动作一 screen（筛选景气板块）                 动作二 pick（选出景气标的）
────────────────────────────                ────────────────────────────
读状态（prosperity_state.py show）            读状态（prosperity_state.py show）
 ├─ 无在跟板块 → 初始化：                      ├─ 无在跟板块 → 拒绝请求并说明原因
 │   联网研究 → 选 2–5 个景气板块               │   （必须先跑 screen，不凭印象选股）
 │   → add 登记（含入选原因）→ 报告             └─ 有板块 → 每板块起 1 个 subagent（并发≤3、
 └─ 有在跟板块 → 复核：                            完成一个补一个），subagent 内完成：
     逐板块取证：景气点/风险点                      选 8–12 支 A股高相关标的（默认 10）
     → 保留（review）/ 新增（add）                  + fetch_quotes 快照 + fetch_forecast 一致预期 + 景气口径估值
     / 剔除（先问用户是否踢观察仓标的）          汇总去重 → 报告 → 问用户确认
     → 报告                                    → add + set --PS 写观察仓
```

两个动作每次运行都把报告写入 `output/prosperity/report_<时间戳>.md`（内容含证据时点），用于追踪景气投资的全过程；状态文件由脚本回写，报告由 agent 按下述格式撰写。

## 动作一：筛选景气板块（screen）

### 第 1 步：读状态

```bash
python scripts/prosperity_state.py        # 默认状态文件 output/prosperity/state.yaml
```

### 第 2 步 A：无在跟板块 → 初始化

输出含「当前没有跟踪中的景气板块」时：

1. 按 `prosperity-analysis` 的三层框架联网研究（自上而下宏观定位 → 中观行业景气 → 业绩兑现确认；核心信号：行业盈利增速方向 + **分析师一致预期上修/下修（二阶导）**），检索当前 A股（沪深北，含北交所）处于盈利景气上行通道的板块（港股公司可作板块景气证据参考，但选标的仅 A 股）。所有证据标注数据时点，取不到证据的方向不下结论。
2. 选出 **2–5 个**当前最景气的板块（宁缺毋滥；景气上行早段优先于情绪饱满的中后段），逐个给出：景气位置、景气信号（具体证据+时点）、盈利方向（一阶导+二阶导）、估值口径（前瞻PE/分位）、风险点。
3. 逐个登记（板块 id 用小写英文短代号，它是观察仓 `PS` param 的值）：

```bash
python scripts/prosperity_state.py add ai-compute --name "AI算力" --reason "光模块订单饱满+盈利预期上修（2025Q1）"
```

4. 写初始化报告到 `output/prosperity/report_<时间戳>.md`，向用户完整汇报每个板块的**入选原因**。初始化不选个股、不写观察仓——那是动作二的事。

### 第 2 步 B：有在跟板块 → 复核

对每个在跟板块重新联网取证，分别列出**景气点**（盈利/订单/价格/预期上修等正向证据）与**风险点**（预期下修、拥挤度、估值分位过高、景气与股价脱钩等负向证据），再扫描一次市场上是否有**新的景气板块**值得新增。结论分三类处理：

- **保留且仍景气**：`python scripts/prosperity_state.py review <板块id> --note "<景气点/风险点一句话结论>"`
- **新增**：同初始化的研究口径 → `add <板块id> --name "<板块名>" --reason "<入选原因>"`
- **剔除（不再景气）**：**必须先问用户**——「是否把观察仓中该板块的标的（`PS=<板块id>`）一并踢出观察仓？」：
  - 用户同意 → 先 `python scripts/manage_watchlist.py`（list）找出带 `PS=<板块id>` 的条目，逐个 `rm <代码>`；随后 `python scripts/prosperity_state.py rm <板块id> --reason "<不再景气原因>"`
  - 用户不同意 / 暂不处理 → 只剔除板块跟踪状态（`rm` 板块），观察仓条目原样保留
  
复核报告写入 `output/prosperity/report_<时间戳>.md`：每个板块的景气点/风险点/结论、剔除与新增汇总、观察仓联动结果。

## 动作二：选出景气标的（pick）

### 第 1 步：门槛（硬拒绝）

`prosperity_state.py show` 输出含「当前没有跟踪中的景气板块」→ **拒绝本次请求并终止**：明确告诉用户景气标的选择必须先有景气板块名单（先运行「筛选景气板块」完成初始化或复核），不要凭印象选股、不要绕过该门槛。有在跟板块才继续。

### 第 2 步：分板块并行选标的与估值（subagent 编排）

对每个在跟板块起一个**后台 subagent**，由它完成该板块的「选标的 → 取行情 → 景气估值」全流程；**并发上限 3**——先同时起前 3 个板块，之后每收到一个完成通知就补起下一个未开始的板块，直到全部板块完成（板块数 ≤3 时一次性全起；会话没有 subagent 工具时退化为串行逐板块自行执行，任务内容不变）。

- **subagent 提示词必须自包含**（它看不到当前会话）：板块信息（id / 名称 / 入选原因 / 最近复核结论，取自第 1 步状态输出）+ 任务内容 + fetch_quotes 命令行（含 token）+ 输出格式，并明确「只做这一个板块，不写观察仓、不改任何状态文件、只返回结构化结果不写文件」。
- **任务内容**（各 subagent 相同，仅板块信息不同）：按相关标准（主营业务与板块景气直接挂钩、营收/利润对板块量价敏感、业务纯度高不蹭概念、行业地位与份额领先）联网研究该板块候选，选出**每板块 8–12 支（默认 10，用户可指定）**核心受益标的——**候选范围仅 A 股**（沪深主板/创业板/科创板/北交所，北交所标的可选；不选港股，其行情与一致预期取数链不全）——板块内按「纯度 + 龙头地位」排序取舍、合格候选不足定额时按实际数量如实说明、不硬凑；对候选跑 `python scripts/fetch_quotes.py --snapshot <代码,...>` 取行情，再逐只跑 `python scripts/fetch_forecast.py <代码> --mcap <总市值亿元>` 取同花顺机构一致预期（前瞻PE/PEG 的分母；总市值取快照值÷10000 换算成亿元）；先完整阅读 `scripts/stock-valuation/` 的 SKILL.md 与 data-source.md，再按景气口径逐只估值，**估值结论与机构一致预期方向相悖或差距显著时必须做差异分析**（预期透支/机构预测滞后/覆盖不足/年内进度不符/口径差异/独立判断，见 stock-valuation SKILL.md 的差异分析要点）并明确采信立场；返回结构化结果（每只：代码 / 名称 / 相关逻辑一句话 / 估值结论（口径+数值）/ 与机构一致预期的差异（无显著分歧或差距原因）/ 风险点，标注数据时点）。

**估值硬约束（subagent 内执行）**：**候选与标的仅 A 股（沪深北，含北交所），不选港股**；**禁止用孤立静态 PE/PB 下「贵/便宜」结论**（周期股 PE 悖论：盈利顶点静态 PE 最低恰是风险，见 `docs/prosperity_investing.md` 第 4 节）；方法论以 `stock-valuation` 为准（生意属性→估值口径→横切维度→收敛）——面板场景先从宿主静态端点 `/plugins/advisor-agent/assets/stock-valuation/` 下载 SKILL.md 与 data-source.md 到 `scripts/stock-valuation/` 通读（不依赖工作区装有该技能），仓库内直接读 `.agents/skills/stock-valuation/`；口径：**前瞻/动态 PE + PEG + 周期中枢盈利（类 CAPE）+ 逆向 DCF 隐含增长率 + 相对估值分位**，叠加质量溢价与拥挤度/交易结构；输出前过一遍其「常见陷阱自检」清单；前瞻PE/PEG 的分母用 fetch_forecast.py 的净利润一致预期均值（结论注明覆盖机构数），取不到时**明确标注数据缺口与替代口径**，不编造；**自己的结论与机构一致预期相悖或差距显著时，必须分析差距原因并给采信立场**——不盲抄机构数字，也不无据否定。

### 第 3 步：汇总核查

全部板块的 subagent 完成后合并结果：同一标的被多个板块选中时只保留一条，`PS` 归属相关逻辑更强的主板块、相关逻辑里注明另一板块；核查每个在跟板块均已覆盖、各板块数量定额执行情况（含不足说明）如实转达；某板块 subagent 失败或超时 → 如实报告该板块缺口、可单独重跑该板块，不编造结果。

### 第 4 步：汇总与写入观察仓（先问后写）

1. 汇总表（呈现给用户并写入报告）：代码 / 名称 / 所属板块（PS id）/ 相关逻辑一句话 / 估值结论（口径+数值）/ 风险点。
2. **询问用户**「是否将上述标的加入观察仓？」，得到明确同意后逐只写入（幂等）：

```bash
python scripts/manage_watchlist.py add 600519 --name "贵州茅台" --note "AI算力景气核心受益" --source prosperity-picking
python scripts/manage_watchlist.py set 600519 --PS ai-compute --PS_DATE 2025-06-03
```

`--PS`（板块 id）/ `--PS_DATE`（打标日期）即**板块 key**：板块日后被剔除时，按 `PS=<板块id>` 从 list 输出快速筛出该板块全部标的、逐个 rm。用户不同意 → 只保留报告，不写观察仓。

## 常见陷阱自检（输出前逐一过）

- [ ] 是否在无景气板块时硬拒了选股请求（而不是凭印象推荐）？
- [ ] 选股数量是否按板块定额执行（每板块默认 10 支、每个在跟板块都覆盖、候选不足不硬凑）？
- [ ] 候选是否全部为 A 股（沪深北，含北交所），无港股混入？
- [ ] 与机构一致预期分歧大的标的，是否说明了差距原因（透支/滞后/覆盖弱/年内进度不符/口径/独立判断）并给了采信立场？
- [ ] subagent 编排是否守住并发上限 3、提示词自包含，且观察仓/状态文件的写入全部留在主流程？
- [ ] 板块剔除前是否先问了用户「观察仓该板块标的踢不踢」？
- [ ] 估值结论是否用了景气口径（前瞻/中枢/PEG/隐含增速/分位），而不是静态 PE/PB？
- [ ] 是否在景气最高、预期最满、估值分位极高处追高（脱钩信号）？
- [ ] 所有证据是否标注了数据时点？前瞻预期数据是否标注了来源或缺口？
- [ ] 观察仓写入是否全部走了 manage_watchlist.py（add + set --PS）？

## 与其它技能的分工

- 行业景气判断方法论（三层框架、景气适配估值口径）→ `prosperity-analysis`（本技能是其执行层，不重复展开）。
- 个股估值方法论（生意属性→估值口径）→ `stock-valuation`（动作二第 2 步的板块 subagent 内直接复用其「景气成长/制造」分支，方法论文档经宿主静态端点分发、任意工作区可下载）。
- 观察仓清单读写 → `watchlist-manager`（本技能委托 `add` + `set --PS/--PS_DATE`；踢标的时按 `PS=<板块id>` 筛选后逐个 `rm`）。
- 当期景气行业快照（全市场分析）→ `prosperity-analysis` 写 `output/sectors/`；本技能的 `output/prosperity/state.yaml` 是**用户跟踪的板块子集**（含进出留痕），两者不互通。
- 持仓（真金白银的仓位）→ `portfolio-tracker`（本技能产出的是观察仓候选，不是持仓建议）。
- 动量排名/W底形态 → `momentum-rotation` / `w-bottom-screener`（与本技能共用观察仓标的池，视角不同：动量/形态 vs 景气）。
- 工作区骨架（`output/prosperity/` 目录）→ `workspace-init`。

## 生成数据 vs 技能方法（提交边界）

- **提交**：本技能（SKILL.md，方法论）+ 脚本真源 `src/workspace-init/prosperity_state.py`（自包含状态管理，随插件包分发）。
- **不提交**：`output/prosperity/`（景气板块跟踪状态与报告，个人研究数据，已被 gitignore）、`output/watchlist/`（观察仓清单）。

## 免责

本技能输出为研究与投教用途，不构成投资建议；景气判断与估值有时点性与滞后性，须标注数据时点；写入观察仓不等于买入建议。
