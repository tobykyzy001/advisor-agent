# 景气板块选股（Prosperity Picking）

把「景气投资」落成一条可持续跟踪的流水线：**先维护一份当前跟踪的景气板块清单，再从这些板块里选出高相关标的放进观察仓**。核心信念同 `prosperity-analysis`：景气度（盈利增速方向）决定相对收益——本技能是它的**执行层**（板块进出 + 标的落地），只负责「谁属于这个板块」，不负责「贵不贵」。

> 定位：这是一个**组合工具**（两段式流水线），把 prosperity-analysis（板块景气判断）、watchlist-manager（观察仓写入）串成闭环，并自己维护一份跨轮次的**景气板块跟踪状态**（`output/prosperity/state.yaml`）。估值不属于本工具——要判断个股贵不贵，另跑 `stock-valuation`。

## 何时触发

- 用户说「筛一下当前有哪些景气板块」「复核一下我的景气板块还在不在」「初始化景气板块」。
- 用户说「看看最近有什么新的热点/景气板块」「把 XX 板块加入跟踪」「只复核/重筛一下 XX 板块」「只给 XX 板块选股」——**范围收窄，不要全量重跑**。
- 用户说「从景气板块里选股」「选一批景气标的」「把景气投资组合建起来」。
- 投研工具面板：侧边栏「景气板块选股」卡片（动作 screen 筛选/复核景气板块、pick 选出景气标的；范围 all 全量 / new 仅扫当前新热点 / only 仅指定板块）。

## 两段式流程（严格按动作分流，不混跑）

```
动作一 screen（筛选景气板块）
──────────────────────────────
读状态（prosperity_state.py show）
 ├─ 无在跟板块 → 初始化：
 │    联网研究 → 选 2–5 个景气板块 → add 登记（含入选原因）→ 报告
 └─ 有在跟板块 → 复核：
      逐板块取证：景气点/风险点
      → 保留（review）/ 新增（add）/ 剔除（先问用户是否踢观察仓标的）
      → 报告

动作二 pick（选出景气标的）
──────────────────────────────
读状态（prosperity_state.py show）
 ├─ 无在跟板块 → 拒绝请求并说明原因（必须先跑 screen，不凭印象选股）
 └─ 有板块 → 每板块起 1 个 subagent（并发≤3、完成一个补一个）：
      ① 清点：该板块相关 A股（通常 20–80，上限 100；默认剔除科创板 688/689）
      ② 相关性裁决：收入/支出/链条三类证据任一即可，不设比例门槛；证不出即出池
      ③ 流动性核验：一次快照，只确认 ST/停牌/低成交额
      汇总去重 → 报告（裁决表 + 排除清单）→ 问用户确认 → 全量 add + set --PS
      （不做估值：不计算 PEG、不用合理价中值、不打估值标签）
```

两个动作每次运行都把报告写入 `output/prosperity/report_<时间戳>.md`（内容含证据时点），用于追踪景气投资的全过程；状态文件由脚本回写，报告由 agent 按下述格式撰写。

## 范围（scope）：别每次都全量重跑

两个动作都支持范围收窄（面板参数/用户指令给出，未指定时默认 **all**）——板块多了以后全量重研究很慢，**日常跟踪优先用 new / only，定期（如按季度）再跑 all 全量复核**：

| 范围 | screen（筛选/复核板块） | pick（选出标的） |
| --- | --- | --- |
| `all`（默认） | 逐板块复核景气点/风险点 + 扫描新热点板块 | 每个在跟板块都选 |
| `new` | 只扫描当前新热点板块（比对去重后决定新增）；**不复核、不改动任何现有板块**，最快 | 无意义（pick 不从新增扫描产出），提示用户改用 all/only |
| `only` + 指定板块 | 只处理指定板块：在跟的重筛复核，**未在跟的（可给中文名，如「固态电池」）研究取证后新增**；不碰其他板块、不做全市场扫描 | 只为指定的在跟板块选股（如只给新增板块补标的）；指定的板块必须在跟 |

指定板块多个时用逗号/空格分隔；板块 id 见 `show` 状态输出（也是观察仓 `PS` param 的值）。

## 动作一：筛选景气板块（screen）

### 第 1 步：读状态

```bash
python scripts/prosperity_state.py        # 默认状态文件 output/prosperity/state.yaml
```

### 第 2 步 A：无在跟板块 → 初始化

输出含「当前没有跟踪中的景气板块」时：

1. 按 `prosperity-analysis` 的三层框架联网研究（自上而下宏观定位 → 中观行业景气 → 业绩兑现确认；核心信号：行业盈利增速方向 + **分析师一致预期上修/下修（二阶导）**），检索当前 A股（沪深北，含北交所）处于盈利景气上行通道的板块（港股公司可作板块景气证据参考，但选标的仅 A 股）。所有证据标注数据时点，取不到证据的方向不下结论。
2. 选出 **2–5 个**当前最景气的板块（宁缺毋滥；景气上行早段优先于情绪饱满的中后段），逐个给出：景气位置、景气信号（具体证据+时点）、盈利方向（一阶导+二阶导）、估值口径（前瞻PE/分位）、风险点。
3. 逐个登记（板块 id 用小写英文短代号，它是观察仓 `PS` param 的值）：

```bash
python scripts/prosperity_state.py add ai-compute --name "AI算力" --reason "光模块订单饱满+盈利预期上修（2025Q1）"
```

4. 写初始化报告到 `output/prosperity/report_<时间戳>.md`，向用户完整汇报每个板块的**入选原因**。初始化不选个股、不写观察仓——那是动作二的事。

### 第 2 步 B：有在跟板块 → 复核（按范围分流）

- **all（全量，默认）**：对每个在跟板块重新联网取证，分别列出**景气点**（盈利/订单/价格/预期上修等正向证据）与**风险点**（预期下修、拥挤度、估值分位过高、景气与股价脱钩等负向证据），再扫描一次市场上是否有**新的景气板块**值得新增。
- **new（仅扫当前新热点）**：只对当前市场做一轮新热点扫描（同初始化研究口径，先与在跟板块比对去重），值得新增的才走「新增」处理；**不复核、不改动任何现有板块**。
- **only（仅指定板块）**：只处理指定板块——在跟的重筛复核（景气点/风险点取证同上）；**未在跟的（用户指名方向，可给中文名）按初始化研究口径取证、确认景气上行才走「新增」**；不碰未指定板块、不做全市场扫描。

结论按类型处理（复核产生保留/剔除，扫描或用户指名产生新增）：

- **保留且仍景气**：`python scripts/prosperity_state.py review <板块id> --note "<景气点/风险点一句话结论>"`
- **新增**：同初始化的研究口径 → `add <板块id> --name "<板块名>" --reason "<入选原因>"`
- **剔除（不再景气）**：**必须先问用户**——「是否把观察仓中该板块的标的（`PS=<板块id>`）一并踢出观察仓？」：
  - 用户同意 → 先 `python scripts/manage_watchlist.py`（list）找出带 `PS=<板块id>` 的条目，逐个 `rm <代码>`；随后 `python scripts/prosperity_state.py rm <板块id> --reason "<不再景气原因>"`
  - 用户不同意 / 暂不处理 → 只剔除板块跟踪状态（`rm` 板块），观察仓条目原样保留
  
复核报告写入 `output/prosperity/report_<时间戳>.md`：每个板块的景气点/风险点/结论、剔除与新增汇总、观察仓联动结果。

## 动作二：选出景气标的（pick）

**核心原则：只判相关性，不做估值。**

- 观察仓是「板块相关标的池」，不是「便宜清单」，也不是「估值排序表」。
- PEG、前瞻PE、合理价、安全边际、估值分位**不属于本工具**——要判断个股贵不贵，另跑 `stock-valuation`。把估值混进选池，会让池子大小随行情抖动（一次板块普涨就能把门槛打没），下游 `momentum-rotation` / `w-bottom-screener` 的输入不可复现，回测也无法验证。
- 本工具唯一要回答的问题：**这家公司的主营业务是不是这个板块、占比多少、证据是什么。**

### 第 1 步：门槛（硬拒绝）

`prosperity_state.py show` 输出含「当前没有跟踪中的景气板块」→ **拒绝本次请求并终止**：明确告诉用户景气标的选择必须先有景气板块名单（先运行「筛选景气板块」完成初始化或复核），不要凭印象选股、不要绕过该门槛。有在跟板块才继续。

### 第 2 步：分板块并行做相关性裁决（subagent 编排）

对目标板块（默认**全部在跟板块**；范围为 only 时**仅指定板块**——指定板块必须在跟，不在跟的如实报告并略过，全部不在跟则终止请用户核对板块 id；pick 无 new 范围）各起一个**后台 subagent**，由它完成该板块的「清点 → 相关性裁决 → 流动性核验」；**并发上限 3**——先同时起前 3 个板块，之后每收到一个完成通知就补起下一个未开始的板块，直到全部目标板块完成（目标板块数 ≤3 时一次性全起；会话没有 subagent 工具时退化为串行逐板块自行执行，任务内容不变）。

- **subagent 提示词必须自包含**（它看不到当前会话）：板块信息（id / 名称 / 入选原因 / 最近复核结论，取自第 1 步状态输出）+ 相关性裁决标准 + fetch_quotes 命令行（含 token）+ 输出格式，并明确「只做这一个板块、不做估值、不写观察仓、不改任何状态文件、只返回结构化结果不写文件」。

**任务内容（各 subagent 相同，仅板块信息不同）**：

1. **清点**：联网研究**该板块相关** A 股标的——范围是「板块成分股 ∪ 主营与该板块直接相关的公司」，这类板块通常几十只；**硬上限 100 只**（超出时按「板块相关业务营收占比 × 行业地位」取前 100，并在结果里说明被截断），**严禁把全市场 5000+ 只当候选池**——板块定义本身就是候选范围的边界；候选仅 A 股（沪深北，含北交所），不选港股。
   - **科创板剔除（默认开）**：面板「剔除科创板 688/689」开关默认 `on`——代码以 **688 或 689 开头**的标的在清点阶段直接排除，不进入候选池、不做相关性裁决、不写入观察仓，在排除清单里按「科创板剔除」记主因。切成 `off` 时才允许科创板标的参与裁决与入池。
2. **相关性裁决（证据制，不设比例门槛）**：满足下列任一证据即可入池；三条都拿不出，一律出池。
   - **收入型**：确有该板块相关业务的营业收入——给出分部收入或主营构成的**金额、报告期与口径**。**不设占比下限**：占比很低但金额、增速可核验的专项业务同样算，只要说清「是哪块业务、多少钱」。
   - **支出型**：该板块相关的采购、资本开支、在建工程或研发投入——给出金额、期间与用途（用于建设该板块产能、采购该板块核心物料、投入该板块研发等）。
   - **链条型**：可核验的传导证据——主要客户及供货内容、中标/订单/框架协议（**须有金额或数量**）、产能或在建项目、上下游参股绑定；必须写清「谁→谁、传导什么」。
   - **排除**：① 上述三类证据都拿不出；② 只有「战略合作/意向/将布局」而无金额、无产能；③ 仅参股形成的投资收益、纯贸易转手（无自研无产能）；④ ST / 退市风险。
   - **禁止用行业分类词充当相关性证据**：「医药制造业」「医药工业」「其他业务」这类无区分力的分类名不算证据——中成药正是靠「医药制造业」命中「医药」混进创新药板块的，而真 CXO 因分部命名不规范反而被剔。分部名无法区分业务时，必须回到产品/客户/订单/支出层面找证据，证不出就**不入池**。
   - **每条入池必须写清证据类型与内容**：标明是「收入型 / 支出型 / 链条型」，并给出具体数值或关系，不写「受益于 XX 景气」这类结论性套话。
   - **盈利与否、有无机构覆盖都不影响相关性判定**——本工具不判断基本面好坏。
3. **流动性核验**：对相关性入池标的（全量）**一次性**跑 `python scripts/fetch_quotes.py --snapshot <池内全部代码逗号分隔>`，只为确认 ST/停牌/长期低成交额等不可交易情形；快照里的 PE/PB **不得作为判断依据**。流动性不足的剔除并记主因。

**返回结构化结果**：入池清单（相关性达标全量，每只：代码 / 名称 / **相关性证据（类型＝收入型/支出型/链条型 + 具体数值或关系 + 来源与时点）** / 相关逻辑一句话 / 风险点）+ 排除清单（代码 / 名称 / 排除主因）+ 统计（清点数 → 相关性纳入 → 排除数按主因分布），全部标注数据时点。**不输出任何估值结论、不做排名。**

### 第 3 步：汇总核查

全部目标板块的 subagent 完成后合并结果：同一标的被多个板块选中时只保留一条，`PS` 归属相关逻辑更强的主板块、相关逻辑里注明另一板块；核查每个目标板块均已覆盖（范围为 only 时核查指定板块）、各板块相关性裁决统计（纳入/排除数、排除主因分布）如实转达；**每板块抽 2–3 只复核相关性证据链**（是否真的用业务占比/产品客户证据，而不是行业分类词）；某板块 subagent 失败或超时 → 如实报告该板块缺口、可单独重跑该板块，不编造结果。

### 第 4 步：写入观察仓（先问后写）

1. 汇总表（呈现给用户并写入报告）：**主表为相关性入池清单**——代码 / 名称 / 所属板块（PS id）/ 相关性证据（类型+数值或关系+来源）/ 相关逻辑一句话 / 风险点；**附表为排除清单**（代码 / 排除主因）与按板块的主因分布。不输出估值结论、不做排名。
2. **询问用户**「是否将上述相关性入池标的加入观察仓？」，得到明确同意后逐只写入（幂等）——**写入的是相关性全量**：

```bash
python scripts/manage_watchlist.py add 688525 --name "佰维存储" --note "DRAM模组｜板块占比78%" --source prosperity-picking
python scripts/manage_watchlist.py set 688525 --PS storage --PS_DATE 2025-06-03
```

`--PS`（板块 id）/ `--PS_DATE`（打标日期）即**板块 key**：板块日后被剔除时，按 `PS=<板块id>` 从 list 输出快速筛出该板块全部标的、逐个 rm。用户不同意 → 只保留报告，不写观察仓。
3. **已在仓但本轮被判弱相关的**（`PS=<板块id>` 且本轮未入池）：在报告里单独列出代码 / 排除主因，**询问用户是否移出，不自动删除**。

```
└── report_<时间戳>.md                  #   每轮筛选/复核/选股的报告（agent 写，含证据时点）
```

`prosperity_state.py` 随插件包分发，面板场景由投研工具在投递指令前预置到 `scripts/`（经宿主 `/provision` 端点白名单直写）执行，仓库内直接 `python src/workspace-init/prosperity_state.py` 运行；pick 场景另预置 `fetch_quotes.py`（仅用于 ST/流动性核验）。观察仓写入一律委托 `watchlist-manager`（本技能对 `output/watchlist/` 零直接写）。

## 常见陷阱自检（输出前逐一过）

- [ ] 是否按本轮范围执行——new 未改动任何现有板块、only 未越界处理未指定板块、pick 未对 new 范围执行选股？
- [ ] 是否在无景气板块时硬拒了选股请求（而不是凭印象推荐）？
- [ ] **是否全程没有做估值**——没有计算/引用 PEG、没用合理价中值或安全边际、没打估值分档、没出估值排名？
- [ ] 弱相关/蹭概念是否用**可核验证据**排除——收入型（金额+期间）／支出型（采购/在建/研发投入）／链条型（客户供货、有金额的订单、产能项目），而不是行业分类词或概念标签？
- [ ] 是否出现过「医药制造业」「其他业务」这类**无区分力分类词**充当相关性证据？（出现即判不合格）
- [ ] 是否有标的靠「战略合作/意向/将布局」这类无金额、无产能的说法入池？（有即不合格）
- [ ] 每条入池是否写明了**证据类型**（收入型/支出型/链条型）与具体数值或关系，而不是「受益于 XX 景气」这类套话？
- [ ] 分部数据缺口是否标注？
- [ ] 候选是否全部为 A 股（沪深北，含北交所），无港股混入？
- [ ] 科创板剔除开关是否按设定执行——`on`（默认）时**没有任何 688/689 开头的标的**进入候选池或写入观察仓，且排除清单里按「科创板剔除」记了主因？
- [ ] 清点是否守住了板块边界（上限 100），没有滑向全市场扫描？
- [ ] subagent 编排是否守住并发上限 3、提示词自包含，且观察仓/状态文件的写入全部留在主流程？
- [ ] 板块剔除前是否先问了用户「观察仓该板块标的踢不踢」？
- [ ] 所有证据是否标注了数据时点？
- [ ] 观察仓写入是否全部走了 manage_watchlist.py（add + set --PS/--PS_DATE）？

## 与其它技能的分工

- 行业景气判断方法论（三层框架、景气适配估值口径）→ `prosperity-analysis`（本技能是其执行层，不重复展开）。
- **个股估值（贵不贵、该给几倍）→ `stock-valuation`**。本技能不调用它、不产出估值结论；用户若想在选池之后判断估值，另起一轮跑 `stock-valuation`。
- 观察仓清单读写 → `watchlist-manager`（本技能委托 `add` + `set --PS/--PS_DATE`；踢标的时按 `PS=<板块id>` 筛选后逐个 `rm`）。
- 当期景气行业快照（全市场分析）→ `prosperity-analysis` 写 `output/sectors/`；本技能的 `output/prosperity/state.yaml` 是**用户跟踪的板块子集**（含进出留痕），两者不互通。
- 持仓（真金白银的仓位）→ `portfolio-tracker`（本技能产出的是观察仓候选，不是持仓建议）。
- 动量排名/W底形态 → `momentum-rotation` / `w-bottom-screener`（与本技能共用观察仓标的池）。**本技能提供的是「相关性全池」**（通常远大于持仓数），广度足够让动量排名的区分度有效；估值判断若需要，由下游或用户另行调用，不在池子里预先过滤。
- 工作区骨架（`output/prosperity/` 目录）→ `workspace-init`。

## 生成数据 vs 技能方法（提交边界）

- **提交**：本技能（SKILL.md，方法论）+ 脚本真源 `src/workspace-init/prosperity_state.py`（自包含状态管理，随插件包分发）。
- **不提交**：`output/prosperity/`（景气板块跟踪状态与报告，个人研究数据，已被 gitignore）、`output/watchlist/`（观察仓清单）。
